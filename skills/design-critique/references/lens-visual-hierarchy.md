# Lens: visual hierarchy

Evaluate: entry point, eye flow, weight distribution, emphasis honesty.

- **Entry point.** Blur test: what reads first? It must be the user's primary task or the screen's identity - if a decorative element or a secondary metric wins, that's a Major.
- **Eye flow.** Trace the intended sequence (F/Z pattern for reading surfaces, focal-hop for dashboards). Look for hierarchy dead-ends (heavy element leading nowhere) and rival focal points fighting within one zone.
- **Weight budget.** Count emphasis techniques in use (size, weight, color, elevation, position, whitespace). More than 2-3 competing loud elements = inflation; recommend which to demote, not just "reduce emphasis".
- **Level integrity.** Same-importance items should share treatment; different importance must differ visibly. Check headings actually outrank their content, primary action outranks secondary everywhere it appears.
- **Emphasis honesty.** Does visual rank match task frequency/importance? Cross-check against what users actually do (product-analytics) when contested - the most-used action buried in an overflow menu is a classic Major.
- **Whitespace as structure.** Grouping should be readable from spacing alone with borders removed; if boxes are doing all the work, proximity is broken.

Common Optimizely-surface pitfalls: dashboard cards all shouting equally; table screens where filters visually outrank data; wizards where the step map dominates the step content.
