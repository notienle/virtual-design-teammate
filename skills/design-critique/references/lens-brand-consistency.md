# Lens: brand and cross-surface consistency

Evaluate whether the screen feels like Optimizely and behaves like its sibling surfaces.

- **System fidelity.** Components are real Axiom components, not lookalikes (verify names/props via MCP); local snowflake variants of buttons, inputs, tags = findings with the canonical component named.
- **Cross-surface conventions.** Navigation placement, page header anatomy, save models, empty-state style, and terminology should match how Configured Commerce / CoCo / OCP / CMS already do it - check a sibling surface before accepting a local invention. Divergence needs a reason; "designer preference" isn't one.
- **Voice in UI.** Copy is clear, confident, helpful, sentence case; no cuteness at the user's expense, no blame in errors, consistent product terminology (the same object called the same noun everywhere on screen). Route rewrites to ux-writing.
- **Iconography.** Icons from the Axiom set (search_icons to verify), consistent stroke/weight/size, one icon = one meaning across the screen.
- **Density and tone coherence.** The screen's formality and density should match its surface family - a playful illustration style inside an admin console is a coherence finding even if pretty.
- **Brand assets.** Logo usage, product naming (current official names, not legacy codenames in UI), and any marketing-adjacent surfaces defer to the optimizely-brand skill's rules.
